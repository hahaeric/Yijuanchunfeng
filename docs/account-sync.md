# Supabase 免费版：账号、阅读进度与统计

当前客户端直接连接 Supabase Auth 与 Postgres，不需要自行购买服务器、域名或部署旧 Node 后端。这里只提供免费项目的接入，不开通付费套餐。免费额度和暂停政策以 https://supabase.com/pricing 为准。

## 首次开通（项目必须属于你自己的账号）

1. 在 https://supabase.com/dashboard 注册/登录，创建 **Free** 组织和项目，保管好数据库密码；不要把密码发到聊天或写入 Git。
2. 在项目 SQL Editor 中执行 `supabase/migrations/202611240001_reading.sql` 全文。脚本创建阅读进度表、每日统计表、权限策略及同步 RPC。
3. 在 Authentication → Providers → Email（界面名称可能调整）启用 Email 登录，关闭 **Confirm email**。本应用保留用户名密码体验，把用户名规范为小写并映射到项目域名形式的内部登录标识 `用户名@项目编号.supabase.co`；这不是实际邮箱，也不会发送邮件，因此必须关闭邮件确认，不支持邮箱找回密码。若误开邮件确认创建了账号，需要管理员在 Auth 后台确认/重建该测试账号。不要使用此项目给其他需要真实邮箱验证的应用共用账号。
4. 在项目 Connect / API 设置中复制 Project URL 和 **publishable key**（旧项目也可用 anon 公钥）。客户端绝不能使用 secret key、service_role key 或数据库密码。
5. 把 `mobile/.env.example` 复制为 `mobile/.env.local`，填入上述两项。该本地配置已被 Git 忽略。云构建也需在 EAS 对应环境配置同名变量，不能只配置电脑上的本地文件。
6. 根目录 `npm start` 进行联调。发布 APK 前进行双设备测试：注册账号、阅读若干条、离线阅读后联网、另一设备登录恢复、同一天同一条去重、退出和切换账号。网页测试使用 `npm run web`。
7. 如需管理员统计，在 Supabase SQL Editor 执行下述授权（将示例用户名换成自己的小写用户名）：

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'your_username@YOUR_PROJECT_REF.supabase.co';
```

授权后重新登录。管理员角色来自服务端 app_metadata，普通客户端无权设置；不要改 user_metadata 充当权限依据。

## 保存哪些数据

- 账号和密码由 Supabase Auth 管理。客户端只安全保存登录会话，不保存密码。
- 云端只保存当前阅读位置、各书位置、已读进度和每日阅读记录。笔记、收藏、设置和拼音修正仅保存本机账户缓存，不上传，也不会恢复到另一台设备。
- 历史按“账号＋日期”一行保存阅读数量，同时保留紧凑的位标记，用于跨设备、离线补传及重试去重，不存逐次点击日志。
- 当前6185条内容每天的标记上限约774字节（不含行、索引及数据库开销），而且按实际最高阅读编号扩展。即使以后读过全库，单账号5年的原始标记也约1.4MB；这只是结构估算，不是免费容量或服务年限承诺。
- `mobile/src/data/reading-ids.json` 是永久阅读编号表，只能在末尾追加，不能重排、复用或删除已有编号。当前容量16384；将来超过时需先调整数据库约束及客户端验证。
- 当前端只拉取历史每日数量和当天已读编号。历史标记留在数据库，既控制流量，也支持老设备晚几天补传。成功上传的历史本机编号会压缩为数量；未确认的新记录保留待重传。

## 同步和隔离

变化1秒后同步；登录、回到前台以及前台每5分钟检查其他设备进度。离线期间保存在账户专属本机缓存，联网后补传。云端暂不可用或免费项目暂停时显示待同步，本机阅读仍可继续。

采用版本条件写入，冲突后重新拉取并三方合并；不同书的进度不会因另一设备的旧副本被覆盖。同一本书同时阅读时，后一次成功提交的实际修改优先。请求期间新产生的阅读保留到下一次同步。每日记录不受进度冲突覆盖，始终去重汇总。

手机使用 SecureStore 保存会话并自动刷新令牌，重启可恢复离线缓存；网页会话仅在内存，刷新后重新登录。缓存按项目地址与不可变账号ID隔离，避免不同项目、同名账号之间串数据。旧 SQLite 账号和缓存不会自动迁移到 Supabase；游客数据也不会自动归入新账号。

以北京时间划分日期，点击下一句计入阅读，暂停只保存位置。周从周一开始，周/月按日、年按月展示。管理员查询按页读取全部匹配记录，支持日期、账号筛选及 CSV 文本分享。旧版本未保存的历史不能补算。离线未确认的跨设备合计，以成功同步后的汇总为准。

## 权限与备份

表启用 RLS，只允许账号读取自己的数据；普通客户端不能直接修改表。写入经限定字段的 RPC 验证，不能上传笔记或指定其他账号ID。管理员查询必须通过服务端角色校验。

同步不是独立的灾难恢复备份。建议定期从 Supabase 导出两张阅读数据表并安全保存；账号恢复也需保留平台账户与 Auth 数据的维护能力。免费套餐可能因低活跃暂停，并不保证长期在线或提供付费套餐的备份能力。

## 验证与发布

运行 `npm ci` 后 `npm test`。测试使用 PGlite 的真实 PostgreSQL 引擎执行迁移和权限验证，无需生产密钥；传输层测试覆盖登录、令牌刷新、冲突和只上传阅读数据。

在 mobile 目录运行 `npx expo export --platform web` 和 `npx expo export --platform android` 验证代码打包。新增 SecureStore 的旧客户端仍需要先安装包含该原生模块的新 APK，不能直接给更早的 APK 推送这版 JS。

在没有真实项目配置时，界面可运行、阅读与本机统计可用，但注册登录和云同步尚未联通。PGlite 测试不替代真实 Supabase Auth / PostgREST 和手机双设备验收。

旧 `server/` 是此前独立 SQLite 实现的留档与测试对象，当前客户端不再调用它，也不用部署其容器。
